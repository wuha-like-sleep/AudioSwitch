AudioSwitch 登录实验组件 · 0.3.5 Preview 1
开发者：wuha-like-sleep

这是可选的 Windows 原生 Credential Provider 实验组件，不是手机自动解锁功能。
请先在有恢复手段的测试电脑验证，不要把它作为唯一登录方式。

本版范围：
- 在微软账户用户的登录选项中增加“AudioSwitch 登录实验”。
- 只接受手动输入的微软账户密码，不接受 PIN、指纹或人脸作为密码。
- 绑定手机后，提交前需由 LocalSystem 桥接服务现场验证手机的认证加密通道。
- 将受保护的凭据提交给 Windows，由系统决定是否认证成功。
- 不保存密码，不自动登录。安装桥接服务，仅在本组件提交时验证绑定手机。
- 不替换、禁用、包装或筛选原有 Windows Hello / PIN / 密码提供程序。
- 无密码微软账户、组织账户、本地账户尚不支持；真实微软账户登录未在发布 CI 验证。

安装需要管理员权限，组件保存在受保护的 Program Files 目录。
普通 AudioSwitch 安装包不安装此组件；无需使用本组件也可正常切换音频。
从应用内“解锁检测 → 登录组件”绑定已配对手机，需要管理员确认。绑定即时生效，不依赖主设置保存。
已绑定模式仅允许同一用户已登录后锁定的会话；不用于首次开机登录。未绑定保留手动密码实验模式。
安装后在 Windows 登录页的“登录选项”选择实验入口，确认账户仍有可用密码后再测试。
失败时使用原有 PIN / Windows Hello 登录。不要向聊天、Issues 或开发者发送密码或 PIN。
从 Windows“已安装的应用”卸载“AudioSwitch 登录实验组件”可删除自身注册、服务及绑定，可能需要重启释放 DLL。

尚缺：真实 iPhone / LocalSystem 蓝牙兼容性、有效微软账户真机认证、凭据初始化和受保护存储、自动提交、锁定会话端到端测试。
通道认证不能证明人在场或精确距离，也未解决中继风险；尚不应作为唯一验证因素。
蓝牙加密检测通过不代表登录认证通过，也不代表已实现手机靠近解锁。
